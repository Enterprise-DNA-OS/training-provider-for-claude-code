# Why no front end

The database holds the learner records. A coding agent uses the CLI to read and change them. Branded HTML reports are read-only files, not a web application.

A screen gives staff guided entry, a learner portal, mobile attendance, per-user permissions and shared workflows. This base does not provide those. The embedded database is a local operator tool, not an offline sync system. A shared Postgres database alone does not add authorisation or solve concurrent approval workflows. Scope these before using real learners.

Omni by Enterprise DNA can build and operate the provider's version with the required interface and integrations. Keep regulated submissions and official credential issuance in the accepted process until a replacement is validated. Nothing here sends or submits.
